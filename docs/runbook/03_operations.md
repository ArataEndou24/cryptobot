# 手順書 03: 運用（テストネット → 本番）

対象: 運用者。コードを読む必要はない。コマンドと、出力の読み方と、判断基準だけを書く。

## 0. 前提

- 手順書 00（Mac）または 01（VPS）の準備が済み、`make doctor` と `make check` が全て正常。
- 手順書 02 でメインウォレットと API ウォレットを作り、`.env` に次の 2 行がある。
  - `HL_API_WALLET_PRIVATE_KEY=`（取引専用の鍵。出金はできない）
  - `HL_MAIN_ADDRESS=`（メインウォレットの公開アドレス）
- `config/settings.yaml` の `exchange.network` が `testnet`。

## 1. 毎回使うコマンド

| コマンド | 何をするか | 注文 |
|---|---|---|
| `make plan` | 今の目標ポジションを表示 | 出さない |
| `make live-once` | 1 回分のリバランスを計算し、出すはずの注文を表示 | 出さない |
| `make live-once-execute` | 1 回分のリバランスを実行 | 出す |
| `make live` | リバランス時刻（UTC 0/4/8/12/16/20 時の 3 分後）ごとに実行し続ける | 出す |
| `make status` | 口座残高、ポジション、停止フラグを表示 | 出さない |
| `make flatten` | 緊急停止。全ポジションを閉じ、新規注文を止める | 出す |
| `make resume` | 停止フラグを解除 | 出さない |

## 2. テストネットでの最初の 1 回

```bash
make status               # 口座残高が表示されれば接続できている
make live-once            # 出すはずの注文を確認する（まだ出さない）
make live-once-execute    # 実際に出す
make status               # ポジションができたことを確認する
```

出力の読み方:
- `安全装置: 正常` でなければ、その理由を読み、対処するまで先に進まない。
- `拒否:` の行は上限を超えたため出さなかった注文。理由が書いてある。
- `見送り:` の行は最小注文額未満などで出さなかった注文。問題ではない。
- `[NG]` の行は取引所に拒否された注文。内容を貼って報告する。

## 3. テストネットでの連続運用（最低 2 週間）

```bash
make live
```

ターミナルを閉じると止まる。Mac をスリープさせない設定にし、`caffeinate -i make live` で動かす。
別のターミナルから `make status` でいつでも状態を見られる。

毎日 1 回、次を確認する。
1. `make status` の資産と最高値からのドローダウン。
2. `data/live/cycles.jsonl` に周期の記録が増えていること（1 日 6 行）。
3. `[NG]` や `エラー:` が続いていないこと。

## 4. 安全装置（自動で働く）

| 条件 | 動作 | 再開 |
|---|---|---|
| 本日の損失が 8%（設定 `max_daily_loss_pct`） | 全て閉じ、翌日（UTC）まで新規注文なし | 自動 |
| 最高値からの下落が 40%（設定 `max_drawdown_pct`） | 全て閉じ、完全停止 | `make resume`（原因を確認してから） |
| 周期の処理で 3 回連続エラー | 新規注文を停止（ポジションは残る） | `make resume` |
| 1 銘柄が資産の 15% 超、総建玉が資産の 2 倍超 | その注文を出さない | 自動 |
| 運用者が `make flatten` | 全て閉じ、完全停止 | `make resume` |

## 5. 本番に移る条件（全て満たすまで移らない）

1. テストネットで 14 日以上、停止せず稼働した。
2. 日次の損益が検証の想定（年率ボラ 25% なら 1 日 ±1.5% 程度）の範囲に収まっている。
3. `[NG]` の注文が全体の 5% 未満。
4. `make check` と `make doctor` が全て正常。
5. 税務の記録方法を決めた（`data/live/cycles.jsonl` に全注文が残る）。

本番への切り替え:
1. 手順書 02 の 4 節に従い、5 万円相当の USDC を入金する（最初はこれ以上入れない）。
2. `config/settings.yaml` の `exchange.network` を `mainnet` に、`live.armed` を `true` にする。
3. `make live-once`（表示のみ）で内容を確認してから `make live`。
4. 1 か月問題がなければ増額を検討する。

## 6. やってはいけないこと

- 停止フラグの理由を確認せずに `make resume` する。
- 検証していない設定変更を本番に入れる。変更は必ず `make backtest` で確認し、研究記録に残す。
- `.env` を誰かに見せる、貼る、送る。
