# 手順書 00: Mac mini（Apple シリコン）での準備

対象: 運用者。Mac mini M4 / 16 GB は研究にも 24 時間運用にも十分な性能がある。
VPS は不要。この手順書を最初に読み、手順書 01（VPS）は当面読まなくてよい。
所要時間の目安: 30 分（データ取得を除く）。

## 1. 開発ツールの導入

ターミナル（アプリケーション → ユーティリティ → ターミナル）を開いて実行する。

```bash
# git と make が入る。ダイアログが出たら「インストール」を押す。数分かかる。
xcode-select --install

# uv（Python の環境管理ツール。Python 本体も自動で入る）
curl -LsSf https://astral.sh/uv/install.sh | sh
```

uv の導入後、ターミナルを一度閉じて開き直す。次を打って版が表示されれば成功。

```bash
uv --version
git --version
```

Homebrew も Docker も今は不要。

## 2. リポジトリの取得と自己診断

```bash
cd ~
git clone <このリポジトリの URL> cryptobot
cd cryptobot
make setup     # 依存ライブラリを入れ、設定ファイルの雛形をコピーする
make doctor    # 環境診断。全て OK になるまで先に進まない
make check     # 自己診断。「全ての検査に合格しました」と出れば正常
```

`make doctor` で NG が出たら、その出力をそのまま貼り付けて報告する。

## 3. 研究用データの取得

初回は 1〜3 時間かかる。途中で Mac がスリープすると止まるので、`caffeinate` を頭に付ける。

```bash
caffeinate -i make data
make data-status
make universe   # 対象銘柄の一覧が表示されれば成功
```

途中で止まっても、もう一度同じコマンドを打てば続きから取得する（取得済みのファイルは飛ばす）。

## 4. 24 時間運用に向けた Mac の設定（今すぐでなくてよい）

テストネット運用を始める段階で行う。

- **スリープさせない**: システム設定 → エネルギー（またはディスプレイ）→「ディスプレイがオフのときに自動でスリープさせない」を有効にする。
- **停電後に自動で起動**: システム設定 → エネルギー →「停電後に自動的に起動」を有効にする。
- **SSH を有効にする**: システム設定 → 一般 → 共有 →「リモートログイン」を有効にする。別の端末から操作できる。
- **自動更新の再起動に注意**: macOS の自動アップデートで勝手に再起動しないよう、「macOS アップデートを自動的にインストール」は無効にし、手動で更新する。
- ボットの自動起動と異常時の再起動は、後の段階で launchd の設定ファイルを用意する（運用者が置くだけで済む形にする）。

## 5. 自宅運用の弱点と対策

| 弱点 | 対策 |
|---|---|
| 停電 | 上記の自動起動設定。可能なら小型の UPS を挟む |
| 回線断 | ボット側で「接続が切れたら新規注文を止め、復帰後に状態を照合する」仕組みを入れる（実装予定） |
| 誰も見ていない時間の異常 | Telegram 通知と、一定時間応答がなければ知らせる死活監視（実装予定） |

資金が増えて自宅運用のリスクが見合わなくなった段階で VPS を検討すれば十分。

## 6. やってはいけないこと

- 秘密鍵、API キー、`.env` の中身をチャットや他人に貼らない。
- `config/settings.yaml` と `.env` を git にコミットしない（除外設定済み）。
- 本番（mainnet）への切り替えは、手順書 03 の条件を満たすまで行わない。
