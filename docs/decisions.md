# 決定記録（Architecture Decision Records）

このプロジェクトで下した重要な決定と、その理由を残す。後から「なぜこうしたのか」を
辿れるようにするため。決定を覆すときは、ここに新しい項目を追加して古い項目に「置換済み」と書く。

書式: 番号、日付、状態、決定、背景、理由、代償。

---

## ADR-001 運用者はコードを読まない前提で設計する（2026-09-02、採用）

**決定**: 運用者（オーナー）がソースコードを読まず、書かず、その必要もない状態で
安全に運用できることを、全ての設計の最上位の制約とする。

**背景**: オーナーは Linux と API とインフラ構築に強く、プログラミングはしない。
コードの監査ができない以上、「コードが正しいこと」を前提に安全を組み立ててはいけない。

**理由**: 堅牢な運用システムは中身を知らない人が安全に扱えるように作られている。
この制約は品質を上げる方向に働く。

**帰結**:
- 運用者が触るのは、設定ファイル 1 枚、コマンド数個、日本語の通知と日報、自己診断コマンドだけ。
- 設定ファイルは未知のキーを拒否し、危険な値を上限で弾く（打ち間違いを黙って通さない）。
- 戦略の正しさと独立した安全装置（リスク上限、キルスイッチ）を設定で固定し、戦略コードから変更できないようにする。
- 本番前に必ずテストネットで一定期間運用し、それを運用者の検証手段とする。
- 全ての出力・エラーメッセージは日本語で、「次に何をすべきか」を含める。

## ADR-002 実装言語は Python（2026-09-02、採用）

**決定**: 全層を Python 3.12 以上で実装する。執行層で将来速度が必要になった場合のみ、その部分を Rust 化する道を残す。

**背景**: Rust への関心があったが、ADR-001 により運用者はコードを読まない。
言語選択の基準は、開発者（AI）の生産性と、研究に使える道具の充実度だけになる。

**理由**:
- 対象の時間軸（1 時間足、4 時間ごと）では処理速度が成果に影響しない。
- 仮説検証のループを高速に回すための道具（polars、統計、可視化）は Python が最も充実している。
- 規律のある Python（型注釈、静的検査、テスト、依存管理）は「安直」ではない。

**代償**: 高頻度取引には向かない。それは資金規模と手数料の面で最初から対象外である。

**採用する道具**: uv（依存管理）、polars（データ処理）、pydantic（設定検証）、ruff と mypy（静的検査）、pytest（テスト）。

## ADR-003 取引所は Hyperliquid を主軸にする（2026-09-02、採用）

**決定**: 取引は Hyperliquid（分散型の無期限先物取引所）で行う。中央集権型取引所（MEXC、Bitget）は取引所アダプタで対応可能にするが主軸にしない。

**背景**: Bybit は 2026 年に日本居住者向けサービスを終了した（新規取引停止 2026-03、強制決済 2026-07）。
金融庁の圧力により、他の中央集権型取引所も同じ道を辿る可能性がある。

**理由**:
- 最小注文が約 10 ドルで、20 万円を 20〜30 銘柄に分散できる。中央集権型は BTC で 1 万円超の最小単位があり分散できない。
- 本人確認不要で、国の方針による撤退リスクが構造的に低い。
- API とテストネットの品質が高く、公式 Python SDK がある。
- 取引専用の API ウォレット（注文はできるが出金はできない鍵）を作れる。サーバーが乗っ取られても資金は盗めない。ADR-001 と相性が良い。
- 手数料は主要な中央集権型と同等かやや安い。

**代償**:
- 自己管理ウォレット。鍵を失えば資金を失う。サポート窓口はない。
- 資金の出し入れは国内取引所 → ウォレット → Arbitrum の USDC → Hyperliquid という手順を自分で行う。
- ブリッジやスマートコントラクトの障害リスクはゼロではない。
- 無登録業者であり、法的保護はない。利益は雑所得として申告義務がある。

## ADR-004 研究用データは Binance の公式配布データを使う（2026-09-02、採用）

**決定**: 検証に使う過去データは data.binance.vision（Binance 公式の無料配布）の USDT 建て無期限先物、1 時間足とファンディングレートを使う。取引所は Hyperliquid だが、研究データは Binance とする。

**理由**:
- 口座も API キーも不要。2019 年末からの完全な履歴がある。上場廃止済みの銘柄も残っている（生存者バイアス対策に必須）。
- Hyperliquid 自身の過去データは期間が短く、主要銘柄の価格は Binance とほぼ一致する。

**代償と対策**:
- 銘柄名の対応表（例: Binance の 1000PEPEUSDT と Hyperliquid の kPEPE）が必要。執行層で対応する。
- ファンディングレートの水準は取引所ごとに異なる。本番では Hyperliquid の実際の値を使い、研究では Binance の値を近似として使う。
- 当月のファンディングは月末まで配布されない。研究では問題にならない。

**確認済みの配布仕様**（2026-09-02）: 月次ファイルは月末から数日遅れる（日次ファイルで補う）。
古い CSV にはヘッダー行がない。時刻はミリ秒。zip ごとに sha256 のチェックサムがある。

## ADR-005 ユニバースはその時点の情報だけで選ぶ（2026-09-02、採用）

**決定**: 対象銘柄は「その時点より前」の売買代金で順位づけする（point-in-time）。
上場から一定日数（既定 90 日）未満の銘柄、直近で取引が止まっている銘柄、データ欠損の多い銘柄は除く。

**理由**: 今の出来高上位を過去に遡って使うと、生き残った銘柄だけを選ぶ偏り（生存者バイアス）が入り、検証結果が実態より良く見える。世界一を目指すなら、まずここで自分を騙さない。

## ADR-006 時間軸は 1 時間足シグナル、4 時間ごとリバランス（2026-09-02、採用）

**決定**: シグナルは 1 時間足で計算し、目標ポジションへの調整は 4 時間ごとに行う。指値注文を優先する。

**理由**: 往復手数料（約 0.1%）に対し、短い時間軸では回転数が増えて手数料が利益を食う。
日足以上では 20 万円の資金効率が悪い。中間の 1〜4 時間足が手数料と分散の両方を満たす。

## ADR-007 戦略の核はクロスセクショナル・モメンタムとファンディング・キャリー（2026-09-02、採用）

**決定**: 第 1 世代の戦略は、ユニバース内で相対的に強い銘柄をロング、弱い銘柄をショートし、
各銘柄をボラティリティで正規化し、ファンディングレートを受け取る側に傾け、
ポートフォリオ全体のボラティリティを目標値に固定するものとする。

**理由**: 学術的に最も繰り返し確認されている効果であり、回転数が少なく、多数銘柄への分散を前提とする。
平均回帰や板情報を使う戦略はこの土台の上に後から乗せる。

## ADR-008 リスク上限は設定ファイルで固定し、戦略から変更できない（2026-09-02、採用）

**決定**: 以下の上限を設定ファイル（risk セクション）で持ち、戦略コードから書き換えられない構造にする。
- 目標年率ボラティリティ（既定 50%）
- 総建玉の上限（既定 資産の 2 倍）
- 1 銘柄の上限（既定 資産の 15%）
- 1 日の最大損失（既定 8%、達したら当日は全て閉じて停止）
- 最大ドローダウン（既定 40%、達したら全て閉じて完全停止）

**背景**: オーナーの許容ドローダウンは 50% だが、50% は回復に 2 倍のリターンが必要な水準であり、
バグや取引所障害が重なった場合に資金がゼロになる余地を残すため、設計上の停止ラインは 40% とする。

## ADR-009 運用環境は VPS、Docker と systemd で構成（2026-09-02、採用）

**決定**: 月額固定の VPS 1 台で運用する。クラウド（AWS 等）は使わない。

**理由**: 時間軸の関係で取引所との物理的距離は影響しない。VPS は料金が単純で、ボット 1 台には十分。
Docker と systemd による構成はオーナーの得意領域。

## ADR-010 テストネットで最低 2 週間運用してから本番、本番は 5 万円から（2026-09-02、採用）

**決定**: 本番切り替えの条件を次のとおりとする。
1. テストネットで 2 週間以上、停止やエラーなく稼働した。
2. テストネットの損益がバックテストの想定範囲内に収まった。
3. 自己診断（`make check`、`make doctor`）が全て正常。
4. 本番は 5 万円から始め、1 か月問題がなければ増額を検討する。

## ADR-011 非暗号資産のトークン化先物は値動きの性質で判別して除外する（2026-09-02、採用）

**決定**: 株式、ETF、商品（金、原油など）をトークン化した先物は第 1 世代の対象から外す。
判別は名前ではなく、直近 60 日の「週末出来高比 < 0.33」または「年率ボラ < 0.15」で行い、
主要暗号資産 13 銘柄は名前で保護する。判定結果は `make universe` で運用者が確認できる。

**背景**: 全 829 銘柄を取得したところ、現時点の出来高上位 30 のうち 10 以上が非暗号資産だった。
名前による除外リストは維持できない。

**理由**: 株や商品は原資産が週末に休むため出来高が激減する。株価指数とステーブルコインは
値動きが暗号資産よりはるかに小さい。この 2 つの性質は名前より頑健で、新規上場にも自動で対応する。

**代償**: 境界に近い銘柄（BTC の週末出来高比 0.40）を誤判定する可能性があるため名前で保護している。
この保護リストと閾値は、研究記録の較正表を根拠に四半期ごとに見直す。
将来、非暗号資産を別戦略の対象として扱う可能性は残す。

## ADR-012 ファンディングレートは銘柄選定に使わない（2026-09-02、採用。ADR-007 を一部置換）

**決定**: 第 1 世代戦略の銘柄選定はモメンタムのみで行う。ファンディングの受け払いは損益に反映するが、
ロング・ショートの傾きには使わない。目標ボラティリティの既定を 50% から 30% に下げる。

**背景**: 全銘柄での分解検証で、ファンディングを選定に使う変種は年 -31%、使わない変種は年 +20% だった。
ファンディングが高い銘柄は上昇中の銘柄であり、それをショートに傾けるとモメンタムに逆らう。

**代償**: ファンディングを「受け取る側に傾ける」収益源は当面放棄する。将来、モメンタムと直交する形
（例: モメンタムが中立の銘柄だけでファンディングを取る）で再検討する余地は残す。
