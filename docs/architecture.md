# アーキテクチャ

## 設計原則

1. **同じ戦略コードが、バックテスト、テストネット、本番で一切変更なしに動く。** 環境の違いは執行層とデータ層だけが吸収する。
2. **未来参照を構造的に不可能にする。** 特徴量は「時刻 t までのデータ」を入力とする純粋関数だけで書く。
3. **戦略は注文ではなく「目標ポジション」を出す。** 合成、リスク調整、検証が単純になる。
4. **安全装置は戦略と独立している。** リスク上限とキルスイッチは設定で固定され、戦略がどう狂っても超えられない。
5. **運用者はコードを読まない。** 出力は全て日本語で、次にすべき行動を含む。

## 層構成

```
[データ層]      取得・正規化・保存。研究用は Binance 配布データ、本番は Hyperliquid API。
     ↓
[特徴量層]      純粋関数。時刻 t までのデータ → 時刻 t の特徴量。
     ↓
[シグナル層]    複数の独立した戦略が「銘柄ごとの目標ポジション」を出す。
     ↓
[ポートフォリオ・リスク層]  目標を合成し、ボラ目標・上限・相関制限をかけて最終目標を決める。
     ↓
[執行層]        目標と現在の差分を、指値優先で埋める。取引所アダプタで抽象化。
     ↓
[監視・キルスイッチ層]  損失上限、API 異常、価格乖離、遅延を検知したら全て閉じて停止。
```

## ディレクトリ

```

docs/decisions.md              決定記録
docs/runbook/                  運用者向け手順書
src/cryptobot/config.py        設定の読み込みと検証
src/cryptobot/doctor.py        環境診断
src/cryptobot/cli.py           運用者向けコマンド
src/cryptobot/data/            データ層（取得、保存、ユニバース選定）
tests/                         自動テスト（`make check` で実行）
data/                          取得したデータ（git 管理外）
```

## データの流れ（現時点で実装済みの範囲）

1. `cryptobot data download` が Binance 配布サーバーの一覧 API で銘柄と月次ファイルを列挙する。
2. 未取得の zip を並列で取得し、sha256 を検証して `data/raw/` に保存する。
3. zip 内の CSV を解析し、時刻を UTC ミリ秒に揃え、銘柄ごとに Parquet に書く（`data/parquet/`）。
4. `cryptobot universe show` が Parquet を読み、その時点より前の売買代金で銘柄を順位づけする。
